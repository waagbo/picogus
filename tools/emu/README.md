# Emulator test harness for PGBOOT and PGDFS

End-to-end tests of the PGBOOT option ROM (`bootrom/`) and the PicoGUS
card-side code (`sw/dfs`, `sw/bootdisk`) without hardware:

```
 QEMU (i386 PC, SeaBIOS)                     pgcard-sim (host process)
 +-----------------------------+   UNIX     +------------------------------------------+
 | FreeDOS / PGBOOT.ROM        |  socket    | core 0: knock/select, 1D1h/1D2h regs      |
 |   in/out 1D0h-1D2h, 1D4h-5h |----------->|   -> real dfs_ctl_* / dfs_data_* / bd_ctl_*|
 | pgbridge ISA device         |  byte      | core 1: real dfs_tasks() -> dfs_server,   |
 |   (8-bit card: word access  |  cycles    |   dfs_fs, bootdisk, FatFs                 |
 |    = 2 byte cycles)         |<-----------| USB stick: raw image file (file diskio)   |
 +-----------------------------+            +------------------------------------------+
```

* `qemu/pgbridge.c` - the QEMU device; `qemu/pgbridge.patch` - the same file
  plus Kconfig/meson wiring, generated by `qemu/mkpatch.sh`.
* `sim/` - `pgcard-sim`. Core 0 register logic mirrors `sw/picogus.cpp`
  (`select_picogus`, `write_picogus_low/high`, `read_picogus_low/high`) for the
  registers the ROM, pgusinit and PGUSDFS use; everything behind the registers
  is the real firmware code compiled for the host.
* `lib.sh`, `run-tests.sh` - image builders and the tests.
* `buscheck.py` - drives the card over the bridge protocol directly (no QEMU)
  the way the ROM does, and checks the PGBOOT registers and frames (test S1).

Nothing large is kept in the repository: QEMU, FreeDOS, the DOS tools, the
simulator build and all test images live in `$EMU_CACHE`
(default `~/pico/emu-cache`: about 1.7 GB with the QEMU source and build
trees, about 200 MB without them, `CLEAN=1 tools/emu/build-qemu.sh` removes
them after installing; the next build re-extracts the tarball).

## Requirements

* macOS or Linux, a C compiler, make, python3.
* QEMU build: ninja, pkg-config, glib, pixman, libfdt
  (`brew install ninja pkgconf glib pixman dtc`). QEMU brings its own meson.
* mtools (`brew install mtools`) for all disk images.
* OpenWatcom in `~/pico/watcom` (or `$WATCOM`) for T0, T9 and T10: the
  harness builds `DFSDIAG.EXE`, `PGUSDFS.EXE` and `PGUSINIT.EXE` out of tree
  into `$EMU_CACHE/dos` with the flags of their Makefiles (nothing is written
  into `pgusdfs/` or `pgusinit/`), again whenever a source is newer.
* The ROM images for T1-T11: `bootrom/PGBOOT.ROM` and `bootrom/PGBOOT88.ROM`
  (`make -C bootrom`, nasm); a test whose ROM is missing reports SKIP.

## Build

```
tools/emu/build-qemu.sh          # downloads qemu-10.2.4, patches, builds i386-softmmu only
make -C tools/emu/sim            # pgcard-sim ($EMU_CACHE/sim-build/pgcard-sim)
```

`build-qemu.sh` configures with `--without-default-features --enable-tcg
--enable-pixman --enable-vnc --target-list=i386-softmmu` (no docs, no GUI
toolkits, no audio, no networking back ends), installs to
`$EMU_CACHE/qemu` and drops the firmware blobs of other targets. When
`pgbridge.patch` changed it swaps the old patch for the new one in the
existing tree (incremental rebuild) and re-extracts only if that fails.
After editing `qemu/pgbridge.c`, run `qemu/mkpatch.sh` and then `build-qemu.sh`.

The simulator Makefile uses the real `sw/bootdisk/*.c` as soon as that
directory defines `bd_init()`, and `sim/bd_stub.c` (answers AX=01h to every
PGBOOT frame) before that; `make -C tools/emu/sim info` says which.
FatFs is `sw/fatfs/source` with `sw/dfs/test/ffconf_host.h` (read/write, LFN,
fast seek), copied next to `ff.h` in the build directory as that Makefile does.

## Run

```
tools/emu/run-tests.sh                 # T0 S1 T1 ... T11 (about 1.5 minutes)
tools/emu/run-tests.sh T0 T3 T4        # a selection
KEEP=1 SIM_LOG=3 tools/emu/run-tests.sh T1
SIM_EXTRA='--busy-polls 300' tools/emu/run-tests.sh    # a slow card: long BUSY phases
ROMDIR=/some/dir tools/emu/run-tests.sh                # other PGBOOT.ROM / PGBOOT88.ROM
```

Every test prints PASS/FAIL/SKIP and a short excerpt of the guest's COM1
output; the evidence stays in `$EMU_CACHE/work/<test>/`:

| file | content |
|---|---|
| `serial.txt` | COM1 of the guest (the DOS batch files redirect everything there) |
| `sim.log` | card trace: register selects, every frame (`REQ #n BDREAD unit=0 count=7 lba=...`, `ANS #n AX=...`), status changes, USB mount |
| `screen-early.txt`, `screen.txt` | text screen (B800h) a few seconds after power-on and at the end: SeaBIOS, ROM and kernel messages |
| `qemu.log` | QEMU's stderr |
| `*.img` | stick, floppy and hard disk images (deleted after a PASS unless `KEEP=1`) |

## Tests

| Test | What runs | What it proves |
|---|---|---|
| S1 | `buscheck.py` against the sim, no QEMU | Card PGBOOT server over the exact bus sequence: `CMD_BDOPTS` signature, image names, nothing open before BDINFO OPEN (state 0, BDREAD -> 80h), BDINFO (state, CHS, total, floppy type, image token), BDREAD (content equals the image, max-size frames, end of image -> 04h), BDWRITE + read back, wrong token -> 06h floppy / 80h hard disk, new token after OPEN and after a floppy name commit, unknown unit -> 01h. Also shows BUSY -> READY. |
| T0 | Native QEMU floppy boot (FreeDOS), `DFSDIAG /INFO /ECHO /DIR /LDIR /MKDIR` | Bridge + transport + real DFS server, without the ROM: detection registers, 16-bit reads at odd ports, word-wide data window both ways, 64..4096-byte frames, FatFs on the stick image, a write (MKDIR) visible with mtools. |
| T1 | `PGBOOT.ROM`, no native disks, stick with `FD.IMG`, sim `--fd FD.IMG` | The ROM boots FreeDOS from the floppy image: POST detection, INT 19h late init, BDINFO OPEN, INT 13h reads (boot sector, FAT, kernel, COMMAND.COM). Also reports whether a DOS write to A: reached `FD.IMG`. |
| T2 | as T1 with `PGBOOT88.ROM` | the 8088 transfer path (`in ax,dx`/`out dx,ax` loops instead of `rep insw`/`outsw`; the ROM's banner says `(8088 forced)`, on the bus both paths are the same byte-cycle pairs) |
| T3 | ROM, stick with an installer floppy + an empty partitioned FAT16 `HD.IMG` (65/16/63, 32 MB), sim `--fd --hd` | INT 13h writes through the ROM: `FDISK /MBR` (MBR code), `SYS C:` (boot sector, KERNEL.SYS, COMMAND.COM), COPY. Verified afterwards with mtools on `HD.IMG` extracted from the stick. |
| T4 | ROM, stick with only `HD.IMG`, sim `--hd HD.IMG` | Booting FreeDOS from the hard disk image (C:), and a write to C:. Uses T3's image if T3 passed in the same run, else a reference image prepared natively (`P4`). |
| T5 | T1 with `--mount-delay-ms 3000` | The ROM's wait loop: the card reports NODRIVE (FFh) for 3 s after power-on, then the stick mounts and the boot continues. |
| T6 | ROM without `-device pgbridge`, native floppy | No card: the ROM prints `PicoGUS not found` (regex `ROM_NOTFOUND_RE`) and SeaBIOS boots the native floppy. |
| T7 | ROM + card, `--fd MISSING.IMG`, native floppy | Card present but no image ready: the ROM reports "file not found" and chains to the BIOS INT 19h, which boots the native floppy. |
| T8 | ROM, `--fd FD.IMG --hd HD.IMG --opts 8` | Both drives presented, option bit 3 boots C: instead of A:. |
| T9 | ROM, FreeDOS on FD.IMG runs `PGUSINIT /fdimage FD2.IMG` | Floppy swap under a running DOS: the card reopens unit 0 and flags a media change, the ROM reports it through INT 13h, DOS re-reads FAT and directory (new label, a file only FD2.IMG has). FreeCOM re-reads AUTOEXEC.BAT by name and offset, so the checks after the swap only exist on FD2.IMG. |
| T10 | ROM boot, then `PGUSDFS D:` | PGDFS and PGBOOT together: the stick as D:, a D: -> A: copy, and DEL/REN of the open `FD.IMG` refused by the card (DELETE/RENAME answer AX=05h in the trace, the file is still on the stick). |
| T11 | ROM, card `--dfsport 0x2a0`, bridge `dataport=0x2a0` | The ROM takes the data window from `CMD_DFSPORT` instead of assuming 1D4h. |
| P4 | native QEMU floppy + IDE disk, no ROM, no card | Helper: the reference hard disk for T4/T8 when T3 did not run (FDISK /MBR + SYS C: through SeaBIOS INT 13h). |

The markers the tests wait for are written by `AUTOEXEC.BAT` with
`ECHO PGBOOT-... > COM1`; there is no power-off, the harness kills QEMU after
the marker and a final screen dump. Timeout per test: `TIMEOUT` (90 s).

## Test images

* FreeDOS 1.3 FloppyEdition (official, sha256-checked,
  `FD13-FloppyEdition.zip` from ibiblio): its 1.44 MB boot disk is the template
  for every floppy (FreeDOS FAT12 boot sector that loads `KERNEL.SYS` by name);
  the installer is removed and `COMMAND.COM`, `FDAPM.COM`, a minimal
  `FDCONFIG.SYS` and the test's `AUTOEXEC.BAT` are added. `SYS.COM` and
  `FDISK.EXE` come from the same disk.
* The stick is a 96 MB FAT32 superfloppy (`mformat -F`), label `PGSTICK`.
* The hard disk is 65 cyl x 16 heads x 63 sectors with one active type-04
  FAT16 partition at sector 63 (`mpartition`, `mformat -H 63`), no boot code:
  that is what T3/P4 install.

## pgcard-sim

```
pgcard-sim --stick IMAGE [--fd NAME] [--hd NAME] [--opts N] [--mount-delay-ms N]
           [--dfsport N] [--busy-polls N] [--socket PATH] [--persist] [--log[=N]] [--logfile F]
```

* The stick mounts `--mount-delay-ms` after the bridge connects (QEMU start),
  then `dfs_on_drive_mounted()` runs like in `usb_msc/msc_app.c` (which also
  opens the PGBOOT images: `dfs_server_drive_mounted()` calls
  `bd_on_drive_mounted()`). Until then the status reads NODRIVE.
* Core 1: `dfs_tasks()` (which also runs `bd_tasks()`) runs whenever the
  socket is idle for 1 ms, after every control/data-port write except a
  pending request, and when the status is polled: a request stays BUSY for
  `--busy-polls` status reads (default 1), so the ROM sees `02 03`, not just
  `03`.
* `--fd/--hd/--opts` are the persisted settings (`Settings.BootDisk`);
  `CMD_SAVE` only logs them. `CMD_FLASH`/`CMD_REBOOT` are not simulated.
* The data window is decoded at the card's current `CMD_DFSPORT` value; the
  bridge only forwards the window it was created with (`dataport=`), so a
  guest that moves the window loses it, as on a machine where the new ports
  are decoded by something else.
* Log levels: 1 registers and frames, 2 every status poll, 3 disk I/O
  (`disk R/W lba n`), 4 every port access.

## Bridge wire protocol

8-byte messages, little-endian: `op, size(1), port(u16), value(u32)`.
QEMU sends `'r'` (read, blocks for a `'R'` reply carrying the byte) and `'w'`
(write, posted). The device sets `impl.max_access_size = 1` and
`valid.unaligned = true`, so the QEMU memory core splits `in ax, dx` /
`rep insw` into two byte cycles, base then base+1, exactly what an 8-bit ISA
card sees (including `in ax, 1D1h`). Properties: `path` (socket, required),
`dataport` (default 0x1d4, 0 = none), `timeout` (seconds to wait for the
socket at start, default 10).

## SeaBIOS and the option ROM

`-option-rom FILE` hands the ROM to SeaBIOS (1.17.0 in QEMU 10.2) through
fw_cfg (`/rom@genroms/PGBOOT.ROM`). SeaBIOS copies it to the option ROM area
(CC80h here, after `kvmvapic.bin` at CA00h) and runs its init entry during
POST ("Running option rom at cc80:0003" in the SeaBIOS debug log, captured
with `-chardev file,id=sb,path=seabios.log -device isa-debugcon,iobase=0x402,chardev=sb`).
PGBOOT hooks INT 19h there, and SeaBIOS leaves that vector alone: at the end
of POST SeaBIOS boots by issuing INT 19h (`startBoot`), so the ROM's handler
runs first, before any SeaBIOS boot entry. The screen shows the PGBOOT lines
right after the SeaBIOS banner with no "Booting from ..." line (T1-T5, T8-T11).
When the ROM has nothing to boot it chains to the previous vector and SeaBIOS
runs its normal boot order: "Booting from Hard Disk... Boot failed", then
"Booting from Floppy..." (T7; QEMU's default order for `-M pc` is hard disk,
floppy, CD). With no card the ROM does not hook INT 19h at all (T6). So no
`-boot order`/`bootorder` tweaking is needed; the tests pass `-boot menu=off`
only to rule out the boot menu prompt.

## Debugging

* `SIM_LOG=3` (or 4) for the card trace, `KEEP=1` to keep the images.
* Run a test by hand: `pgcard-sim --stick stick.img --fd FD.IMG --log --socket /tmp/pg.sock &`
  then `qemu-system-i386 -M pc -m 16 -display none -nic none -serial stdio
  -option-rom bootrom/PGBOOT.ROM -device pgbridge,path=/tmp/pg.sock`.
  To watch the screen, add `-vnc :1` and connect a VNC viewer to port 5901
  (QEMU is built without curses/SDL/Cocoa).
* The sim exits when QEMU disconnects (`--persist` keeps it listening); a
  guest reboot inside one QEMU run keeps the card state (the simulator has
  no ISA RESET line).
* QEMU: `-d int,in_asm -D qemu.trace` (large), `-d unimp,guest_errors`,
  `-monitor stdio` then `info registers`, `x/16xb 0xc8000`,
  `pmemsave 0xb8000 4000 screen.bin`.
* The screen dumps (`screen*.txt`) come from `pmemsave` of B800:0000 through
  the HMP monitor socket.
